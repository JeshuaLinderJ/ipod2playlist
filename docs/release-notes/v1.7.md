ipod2playlist can now back up your iPod's music, check your setup, preview a run without changing anything, and let you approve close matches by hand. A deleted playlist is noticed before any YouTube quota is spent, and common mistakes show a short message instead of a crash. The README walks you through it step by step.

## Upgrading from v1.5

| v1.5 | v1.7 |
|---|---|
| Playlist deleted online: delete `progress.json` (which also wiped the other service) | `ipod2playlist spotify --new-playlist` (or `youtube`); resets only that service |
| Spotify logs in once | **The first Spotify run asks for one extra browser login** (new `user-library-read` permission, used to see whether your playlist still exists) |
| `missing` writes a TSV | `review` then `apply-review` (check close guesses, add the ones you approve). `missing` still works |
| Copy the music by hand | `ipod2playlist backup "/Volumes/<iPod name>" <folder>` |
| Guess whether setup is right | `ipod2playlist doctor` |
| Run and see | `spotify --dry-run`, `youtube --dry-run` |
| WAV files appear under scrambled names | `scan --itunesdb` (optional) |
| Nothing for other music services | `export-csv` for Soundiiz or TuneMyMusic |

`progress.json` and `songs.json` from v1.5 keep working, so no re-scan is needed. Re-scan only if you want to use `--itunesdb`. This is a one-way upgrade: once you scan with 1.7, the new `songs.json` will not load in 1.5, so re-scan if you ever go back.

To get close guesses for songs already marked missing, run with `--retry-missing`. This uses quota on YouTube. Songs recorded as missing because they were untagged do not need it: after a `--itunesdb` re-scan their names change, so the next normal run searches them automatically.

## New

- **`backup`**: copies every song off the iPod to a folder on your Mac, resumable and never overwriting, and writes M3U8 playlists you can import into Music.app (File > Import) or VLC. Read-only on the iPod.
- **`doctor`**: checks your setup without calling Spotify or YouTube, and ends with a `Next:` line saying what to do.
- **Dry run**: `spotify --dry-run` shows what would be added; `youtube --dry-run` says how many days of quota the run needs, without spending any.
- **`review` and `apply-review`**: close but unsure matches are saved. You mark y or n in a CSV (or look at the HTML page), and only the saved guess is ever added.
- **`scan --itunesdb`** (optional): reads the iPod's own database for the names of untagged songs, ratings, play counts and playlists. The most-played songs go first. It works on a copy and never writes to the iPod.
- **`export-csv`**: writes `library.csv` and a CSV per iPod playlist for Soundiiz or TuneMyMusic. Try a 3-song file first.

## Better matching

- "Live" in a title is handled: "Live and Let Die (Live)" no longer matches the studio song, and the band Live can be found.
- "[4K]" tags and years in brackets no longer make a good match fail.
- "The Beatles" and "Beatles" are treated as the same artist.

## Fixes

- A deleted playlist is detected before any search, so it no longer burns the YouTube quota.
- `--new-playlist` resets one service instead of both.
- Clean one-line messages instead of crashes for a missing `.env`, a Spotify user who is not registered, a YouTube permission error, a bad login, an unreadable client file and a lost connection.
- Ctrl-C stops cleanly with progress saved (exit code 130).
- Tabs, quotes and line breaks in song tags no longer break `songs.tsv`.
- Odd values in a song list (empty or numeric tags) and an empty `progress.json` no longer crash.
- A run with no songs to process no longer creates an empty playlist.
- Untagged songs ("Unknown Artist") are no longer searched, which saves quota.
- A run now stops after 3 song failures in a row (e.g. login revoked or network down) instead of failing every remaining song.

Exit codes: 0 fine, 1 error, 2 YouTube quota reached, 3 playlist no longer exists, 130 Ctrl-C.

## Known limitations

- YouTube still allows about 66 songs a day on the free quota.
- The Spotify app owner needs Spotify Premium, and a new app allows at most 5 users; add each family member's account in the app's user settings.
- pygpod, the package behind `--itunesdb`, is Beta, and macOS is lightly tested upstream. The `--itunesdb` commands also need to be run from the cloned project folder.
- Whether Soundiiz and TuneMyMusic accept our CSV columns is unverified (Soundiiz's own sample has more columns).
- Backup to a FAT-formatted drive: a re-run right after a daylight-saving change may copy the library again (unverified; rsync has the same limitation). Accented folder names on HFS+ or FAT drives may appear in a different Unicode form in playlists; fine on a Mac, but some non-Mac players may not match them.
- Tested on macOS only.
- Python 3.10 works but shows a Google warning.

## Under the hood

279 automated tests (`uv run pytest -q`) use a virtual iPod and stand-in Spotify and YouTube services, so they run offline in a few seconds.
