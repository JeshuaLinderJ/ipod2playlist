# ipod2playlist 1.7 — implementation plan

Release 1.7 does two things. It fixes the Important findings and the cheap Minor findings from
`docs/research/2026-10-28-v1.5-quality-audit.md`, and it adds the five shortlisted features from
`docs/research/2026-10-28-feature-scope.md`: backup with M3U8 export, `doctor` with dry run,
missing-songs review, optional iTunesDB reading, and a CSV export.

Branch: `release/1.7`. Tasks run strictly in order, one implementer per task. Each `## Task N` section
stands alone.

## Spec

### Problems being fixed (audit IDs)

| ID | Problem | Task |
|---|---|---|
| I1 | The README and CLI hint say "delete progress.json". That wipes both services and creates duplicate playlists. | 5 |
| I2 | A deleted playlist burns the whole YouTube quota every day: each song pays for a search, then its add fails. | 3, 4 |
| I3 | First-run mistakes (no `.env`, unregistered Spotify user, YouTube 403) end in raw tracebacks. | 5 |
| I4 | `--songs`, `--progress`, `--public`, `--retry-missing` and YouTube `make_client` refresh/re-login are untested, and mutations to them survive. | 2, 3, 5 |
| M1 | `write_tsv` breaks on tabs or newlines in tags. | 1 |
| M3 | "Live and Let Die (Live)" matches "Live and Let Die". The band Live never matches on YouTube. | 2 |
| M4 | "[4K]", a bracketed year, and "Beatles" vs "The Beatles" make good matches fail, which wastes quota. | 2 |
| M5 | An empty song selection still creates an empty playlist (50 YouTube units). | 4, 5 |
| M6 | `progress.json` holding `{}` or `[]`, or a songs.json with `null` or numeric tags, crashes with a traceback. `scan --songs missing_dir/x.json` also crashes. | 1 |
| M8 | `scan` accepts `--progress` and ignores it. `--client-secrets` and `--token` have no help text. | 5 |
| M9 | Legibility nits in `scan._first`, cli loop, getattr, untyped sync, `QuotaExceeded` living in youtube, magic thresholds. | 1, 2, 3, 4, 5 |
| M11 | Ctrl-C prints a traceback. | 5 |
| M12 (part) | `FakeYouTube.list` accepts any keyword, and the fakes have no 404 behaviour. | 3 |
| M13 | A `None` item in Spotify search results makes the song fail on every run. | 3 |
| M14 | Untagged ("Unknown Artist") songs are searched even though they can never match, at 100 YouTube units each. | 4 |

### Deferred Minor findings (not in 1.7)

- **M2: Python 3.11 floor.** It conflicts with the owner's constraint (Python >= 3.10). Instead,
  `doctor` (Task 7) prints a note that 3.10 works but Google prints a warning.
- **M7: NFC-normalised song keys.** This changes `progress.json` keys. A song with NFD tags would be
  searched again and added a second time, which is a duplicate in the playlist. Doing it safely needs a
  key migration for a rare case.
- **M10: progress is rewritten after every song.** Measured at under 1% of run time.
- **M12 (rest): replacing the fakes with real clients over mocked HTTP.** This is a test-suite rewrite.
  Task 3 tightens the one fake signature the audit flagged and adds realistic 404 behaviour.
- **I2 (secondary): stopping after N consecutive failures.** The audit's other loop case was revoked
  auth or no network. Neither burns quota, so the cost is noisy output, not lost quota.
- **M8 (env var).** `YOUTUBE_CLIENT_SECRETS` stays and is documented (Task 13). Removing it could break
  someone's setup.

### Target behaviour (1.7 command surface)

```
ipod2playlist scan ROOT [--songs P] [--itunesdb]           # songs.json + songs.tsv (+ ipod_playlists.json with --itunesdb)
ipod2playlist spotify [--songs P] [--progress P] [--name N] [--public] [--retry-missing] [--new-playlist] [--dry-run]
ipod2playlist youtube [same as spotify] [--only-spotify-missing] [--client-secrets F] [--token F]
ipod2playlist missing --service S [--songs P] [--progress P]     # unchanged: S_missing.tsv, no API calls
ipod2playlist review  --service S [--songs P] [--progress P]     # S_review.html + S_review.csv, no API calls
ipod2playlist apply-review --service S [--file F] [--progress P] [--client-secrets F] [--token F]
ipod2playlist doctor [--songs P] [--progress P] [--client-secrets F] [--token F]   # no API calls, writes nothing
ipod2playlist backup ROOT DEST [--itunesdb]                       # read-only copy + M3U8 playlists
ipod2playlist export-csv [--service S] [--songs P] [--progress P] [--out F]   # Soundiiz/TuneMyMusic CSV
```

Exit codes:
- 0: success.
- 1: a handled error. The process ends with `SystemExit("<one-line message>")`.
- 2: YouTube quota reached (unchanged), or an argparse usage error.
- 3: the saved playlist no longer exists.
- 130: Ctrl-C.

### Data compatibility

- **`progress.json`** keeps `"version": 1`. The only addition is an optional per-service `"maybe"`
  block (Task 8), written only when a near miss exists. A v1.5 file loads unchanged. v1.5 code reads a
  v1.7 file without problems: it only uses `playlist_id` and `songs`, through `.get`. No migration is
  needed. Task 8 tests both directions on a literal v1.5 file.
- **`songs.json`** gains two optional integer fields, `rating` (0–5 stars) and `plays`, both defaulting
  to 0 (Task 10). v1.5 song lists load unchanged. Song keys (`artist|title`) are unchanged, so existing
  progress still applies.

### Non-goals (do NOT build)

- Writing anything to the iPod, ever: no tags, no database, no lock files.
- Auto-accepting near misses or lowering `MATCH_THRESHOLD`.
- Building Spotify or YouTube playlists from the iPod's own playlists. That would need matched item IDs
  in progress, which is a schema change. 1.7 exports those playlists as M3U8 and CSV instead.
- ytmusicapi, several Google Cloud projects, Apple Music, Deezer or Tidal APIs, AcoustID, ISRC lookups,
  any GUI, Docker.

## Global Constraints (bind every task)

- **The owner's doctrine, in priority order:**
  1. **It works, verified by running.** Run `uv run pytest` and any command you changed. Paste the
     output into your report.
  2. **Legibility: explicit beats compact.** Plain functions, small dataclasses, `if` statements rather
     than clever one-liners. Comments say *why*.
  3. **Simplicity: no unrequested options or abstractions.** No registries, base classes or plugin
     systems. Do not add flags beyond those named in your task.
  - Use the stdlib first, then the existing dependencies, then a maintained package, before
    hand-writing anything. Existing dependencies: mutagen, spotipy, google-api-python-client,
    google-auth-oauthlib, rapidfuzz, python-dotenv. Tasks 10 and 11 add pygpod (optional) and
    pathvalidate.
  - **Surgical changes.** Touch only the files and functions your task names. Do not reformat,
    rename or "tidy" anything else.
- **Persona:** a non-technical family member on macOS. Default to safe behaviour:
  - **never write to the iPod;**
  - **never add a wrong song** (matching stays strict by default);
  - **never lose progress;**
  - keep `progress.json` backward-compatible with v1.5 (see Spec → Data compatibility). If a task
    changes the format beyond what this plan allows, it must add a migration and a test, and say so in
    the report.
- **No test touches the network or a real iPod.** Use and extend the fakes in `tests/fakes.py` and the
  `fake_ipod` fixture in `tests/conftest.py`. Tests that would look at `/Volumes` must pass a
  `tmp_path` instead. Tests assert behaviour, not implementation details.
- **Modules stay under ~150 lines.** New features get their own module. `cli.py` is a thin dispatcher:
  it holds the argparse parser and the error boundary. Command handlers live in `commands.py` (created
  in Task 5). Each handler is about 15 lines: it loads inputs, calls one or two functions in the
  feature module, and prints. All logic and message text live in the feature modules (`playlist.py`,
  `messages.py`, `doctor.py`, `review.py`, `itunesdb.py`, `backup.py`, `export.py`). There is no
  exemption: `commands.py` itself stays under ~150 lines.
- **Python >= 3.10, managed with uv.** After a dependency change, run `uv lock` and commit `uv.lock`.
- **User-facing messages are part of the spec.** Where a task gives an exact message, use it
  character for character, because tests and the README quote them.
- `uv run pytest` passes at the end of every task. Do not leave skipped or xfail tests behind, except
  the `pytest.importorskip("pygpod")` guard named in Task 10.
- **Commit at the end of each task** on `release/1.7`, with a descriptive message whose last line is
  the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not switch branches. Do not
  edit `README.md` before Task 13.

## Task 1: Input hardening (M1, M6, M9 in scan)

Files: `src/ipod2playlist/library.py`, `src/ipod2playlist/scan.py`, `src/ipod2playlist/progress.py`,
`src/ipod2playlist/cli.py` (only `_load_songs`, `_load_progress`, `_scan`), `tests/conftest.py`
(only the `fake_ipod` fixture), `tests/test_library.py`, `tests/test_progress.py`, `tests/test_scan.py`,

**library.py**
- Add the constants `UNKNOWN_ARTIST = "Unknown Artist"` and `UNKNOWN_ALBUM = "Unknown Album"`.
- `write_tsv(songs, path)`: rewrite with the stdlib `csv` module. Open with `open(path, "w",
  encoding="utf-8", newline="")` and use `csv.writer(f, delimiter="\t", lineterminator="\n")`.

## Task 2: Matching strictness (M3, M4, I4 matching, M9 constants)

Files: `src/ipod2playlist/matching.py`, `tests/test_matching.py`.

The rule for every change here: **a fix may accept a song only when the artist gate, the number gate
and the version-word gate all still hold.** Do not touch `fuzz.ratio`, and do not lower any threshold.

- **M9:** named constants `ARTIST_GATE = 85` and `MATCH_THRESHOLD = 80`.
  - `best_match(song, candidates, threshold: float = MATCH_THRESHOLD)`.
  - Shorten the 130-character docstring line in `score`.
- **M3, live counting:** compare version words with `collections.Counter` instead of `set`. That way
  "Live and Let Die" (one "live") never matches "Live and Let Die (Live)" (two).
- **M3, band named Live:** before counting version words in the *candidate* title, strip a leading
  `"<song artist> - "` from the casefolded raw candidate title, when present. The artist's own name then
  does not count as a version word.
- **M4, noise:** add `4k` to `_NOISE_WORDS`, so `[4K]` and `(4K Remaster)` are dropped. Add a
  bracketed-year pattern so `(1975)` and `[2009]` (a 4-digit year 1900–2099 alone in brackets) are
  dropped by `normalize`. A bare year outside brackets stays: "1999" by Prince keeps its number.
- **M4, "The":** in the artist gate only, compare names after removing one leading `"the "` from both
  sides (after `normalize`). This only affects the `fuzz.ratio(artist, channel)` comparison.

**Required tests** (keep all existing tests green; add these):
- `song("Live and Let Die", "Paul McCartney & Wings")` vs `cand("Live and Let Die (Live)", "Paul McCartney & Wings")` → None.
- `song("Lightning Crashes", "Live")` vs `cand("Live - Lightning Crashes (Official Video)", "LiveVEVO")` → match.
- `song("Lightning Crashes", "Live")` vs `cand("Live - Lightning Crashes (Live at Woodstock)", "LiveVEVO")` → None (the real live version is still rejected).
- `song("Song 2", "Blur")` vs `cand("Blur - Song 2 (Official Music Video) [4K]", "Blur")` → match.
- `song("Bohemian Rhapsody", "Queen")` vs `cand("Queen - Bohemian Rhapsody (1975)", "Queen Official")` → match.
- `song("1999", "Prince")` vs `cand("1998", "Prince")` → None (a bare number still gates).
- `song("Let It Be", "Beatles")` vs `cand("Let It Be", "The Beatles")` → match, and the reverse direction too.
- `song("Hello", "The Beatles")` vs `cand("Hello", "The Beat")` → None (dropping "the" must not open the gate).
- **I4 (kills `ratio` → `partial_ratio`):** `song("Yesterday", "The Carpenters")` vs
  `cand("Yesterday Once More", "The Carpenters")` → None.

Note: the Carpenters, "The Beat" and Prince tests already pass on v1.5 (baselines measured); they guard
against mutations. The Live (Live) test is the one that fails on v1.5.

`report` returns lines, each starting with `ok   `, `!!   ` or `note `. They come in this order:
1. **iPod.**
   - For each found iPod: `ok   iPod found: {path}`.
   - None found: `!!   No iPod found in {volumes}. Plug it in and tick "Enable disk use" in Finder (README step 4).`
2. **Song list.**
   - songs.json loads: `ok   {n} songs in {songs_path}`.
   - Missing: `!!   {songs_path} not found.`
   - Invalid: `!!   {songs_path} is not a valid song list; re-run scan.`
3. **Spotify.**
   - For each of `SPOTIPY_CLIENT_ID`, `SPOTIPY_CLIENT_SECRET` and `SPOTIPY_REDIRECT_URI` that is
     missing or empty: `!!   {NAME} is not set; add it to the .env file (README step 2).`
   - If all three are set: `ok   Spotify settings found`.
   - If the redirect URI contains `localhost`:
     `!!   SPOTIPY_REDIRECT_URI uses "localhost"; use http://127.0.0.1:8080/callback (README step 2).`
   - Always: `note Spotify needs the app's owner to have Spotify Premium, and a new app allows at most 5 users; add each person's account in the app's settings on the Spotify Developer Dashboard.`
4. **YouTube.**
   - `secrets_path` is missing: `note {secrets_path} not found; only needed for YouTube (README step 3).`
   - It is JSON with an `"installed"` key: `ok   YouTube client file found`.
   - Anything else: `!!   {secrets_path} is not a Desktop-app OAuth client file (README step 3).`
   - If `token_path` exists: `ok   Logged in to YouTube before ({token_path})`.
5. **Progress.**
   - For each service in `progress.services()`:
     `ok   {service}: {added} added, {missing} missing, playlist {"saved" if id else "not created yet"}`.
   - An invalid file: `!!   {progress_path} is corrupt.`
   - Use `Progress` and `keys_with_status`. Never call `save`.
6. **YouTube estimate**, only if songs loaded:
   - `candidates` = the spotify-missing songs if `"spotify" in progress.services()`, else all songs;
   - `n = sync.search_count(candidates, progress, "youtube")`, so untagged songs (never searched) are not
     counted, and `days = youtube.days_needed(n, progress.playlist_id("youtube") is not None)`;
   - print `note About {days} day(s) of free YouTube quota for {n} songs ({SEARCH_COST + INSERT_COST} units each, {DAILY_QUOTA} a day).`
7. **Python.** If `sys.version_info < (3, 11)`:
   `note Python 3.10 works, but Google's library prints a warning about it; Python 3.11 or newer avoids that.`
8. **Next step.** Exactly one line, `Next: ...`, the first that applies:
   - no songs → `Next: ipod2playlist scan {quoted(first iPod)}`, or
     `Next: plug in the iPod, then ipod2playlist scan "/Volumes/<iPod name>"` if none is found;
   - Spotify settings incomplete → `Next: fix the Spotify settings above (README step 2).`;
   - no spotify block (`"spotify" not in progress.services()`) → `Next: ipod2playlist spotify --dry-run  (then ipod2playlist spotify)`;
   - YouTube songs pending and the client file is ok →
     `Next: ipod2playlist youtube --only-spotify-missing`;
   - otherwise → `Next: all done. ipod2playlist review --service spotify shows what is still missing.`

## Task 9: Review report and apply-review

A human decides every close-but-unsure match. **The only id ever added is the one saved in

**review.py** (stdlib only: `csv`, `html`, `string.Template`, `urllib.parse`, `dataclasses`)
```python
COLUMNS = ["Add? (y/n)", "Title", "Artist", "Album", "Best guess", "Guess link", "Search Spotify", "Search YouTube", "Key"]
def search_links(song: Song) -> tuple[str, str]

def read_decisions(path: Path) -> tuple[list[str], list[str]]

    # csv.Sniffer().sniff(sample, delimiters=",;\t") (a Spanish-locale Excel saves with ";").
    # "y"/"yes"/"s"/"si"/"sí" (case-insensitive, stripped) = accept; "n"/"no" = reject; anything else is ignored.
def write_reports(songs, progress, service: str, folder: Path) -> tuple[int, int]
    # builds review_rows, writes {service}_review.csv and {service}_review.html into folder;

@dataclass
class ApplyResult:

    rejected: int = 0

def apply_review(accepted: list[str], rejected: list[str], service, progress: Progress) -> ApplyResult
```

`apply_review` works as follows:
- **Setup.** Read `playlist_id = progress.playlist_id(service.name)`.
  - If it is None: `raise SystemExit(f"No {service.name} playlist yet; run `ipod2playlist {service.name}` first.")`.
  - If `not service.playlist_exists(playlist_id)`: `raise PlaylistGone(service.name)`.
- **Accepted key:**
  - Skip it (count `skipped`, print `skipped (no saved guess): {key}`) unless both hold: its status is
    `"missing"` and `progress.maybe(...)` exists.
  - Otherwise `service.add(playlist_id, maybe["id"])`, then `progress.record(..., "added")`, then
    `progress.save()`, then print `+ added: {maybe title} by {maybe artist}`.
- **Rejected key:** `clear_maybe`, then save, then count `rejected`. The status stays missing.
- **Errors.** `QuotaExceeded` and `PlaylistGone` propagate. Each add is saved before the next, so
  nothing is lost.

**Commands**
- **`review --service {spotify,youtube}`** (`--songs`, `--progress`): no API calls.
  `run_review` loads the songs and progress, calls `review.write_reports(songs, progress, service,
  Path("."))`, and prints `review.report_message(...)`. It writes `{service}_review.csv` and
  `{service}_review.html` in the current folder, then prints:
  `Wrote {n} missing songs ({g} with a close guess) to {service}_review.html and {service}_review.csv.`
  `Open the .html file to check each guess. In the .csv, type y or n in the "Add? (y/n)" column, save it as CSV, then run: ipod2playlist apply-review --service {service}`
- **`apply-review --service {spotify,youtube}`**:
  - flags: `--file` (default `{service}_review.csv`), `--progress`, `--client-secrets`, `--token`
    (same defaults as `youtube`). There is no `--songs`: `apply_review` works from progress alone;
  - `run_apply_review` calls `review.check_file(args.file, args.service)` first (so a missing file
    never triggers a login), then builds the service with `commands.build_service(args.service, args)`.
    `build_service` already reads `args.client_secrets` and `args.token`, which is why `apply-review`
    defines both flags;
  - then `review.apply_file(args.file, service, progress)` and prints `review.apply_summary(result)`:
    `{added} added / {rejected} rejected / {skipped} skipped`;
  - a missing `--file`: `raise SystemExit(f"{args.file} not found; run `ipod2playlist review --service {service}` first.")`.

**Required tests**

## Task 10: Optional iTunesDB reading via pygpod (read-only, on a copy)

Files: `src/ipod2playlist/itunesdb.py` (new), `src/ipod2playlist/library.py` (Song fields `rating` and

**What was verified** in pygpod 0.2.3, installed in a throwaway venv on 2026-10-28 and run against
databases it wrote itself:
- PyPI facts: `requires_python >=3.8`, LGPL-2.1-or-later, no required dependencies. Extras: `tags`
  (mutagen), `artwork` (Pillow), `usb` (pyusb).
- **Import warning.** `import pygpod` emits a `UserWarning` ("pygpod: optional dependencies not
  installed: Pillow ..., pyusb ...") when Pillow or pyusb are missing. Import it inside
  `warnings.catch_warnings(): warnings.simplefilter("ignore")`.
- **Finding the database.** `from pygpod.device.mountpoint import find_itunesdb`;
  `find_itunesdb(str(root)) -> pathlib.Path | None`. It only lists directories, case-insensitively.
- **Opening a copy.** `pygpod.Database(str(copy_root), recover=False, apply_play_counts=True)` opens a
  folder that holds only `iPod_Control/iTunes/<copied files>`.
  - `recover=False` is documented as "opens read-only-style without touching any file".
  - Play counts and ratings recorded since the last iTunes sync are merged in memory only.
  - **Never** use `with Database(...)`, because `__exit__` saves if modified. **Never** call `save()`.
- **Tracks.** `db.tracks` is a list of `Track`, with:
  - `.title`, `.artist`, `.album` (str; `""` when empty);
  - `.ipod_path`, e.g. `":iPod_Control:Music:F05:UVWX.wav"`;
  - `.rating_stars` (0–5, from `.rating` 0–100);
  - `.play_count` (int).
- **Playlists.** `db.playlists` is a list of `Playlist`, with `.name`, `.is_master`, `.is_podcast`,
  `.is_smart`, and `.tracks` (a list of Track). The master playlist is named after the iPod (e.g.
  `"iPod"`).
- **Errors.** Garbage bytes raise `pygpod.ParseError`. Every pygpod error subclasses
  `pygpod.PyGpodError`.
- **Fixture building.** This works offline: `pygpod.init_ipod(str(root))`, then
  `pygpod.Database(str(root))`, then `db.add_track(path, copy=False, title=..., artist=...,
  album=..., rating=0-100, play_count=N)`, then `db.create_playlist(name)`, then
  `db.add_track_to_playlist(pl, track)`, then `db.save()`.
  - `copy=False` references a file already under `iPod_Control/Music`, keeping its name.
  - `init_ipod` adds only directories and `iPod_Control/Artwork/ArtworkDB` (no audio).
  - `add_track` of a `.flac` raises `UnsupportedFormatError`, so do not add the FLAC fixture.
- **Read-only proof.** After opening a copy, every file of the source tree had identical sha256.

**itunesdb.py** (about 100 lines; pygpod is imported only inside `_import_pygpod()`):
- `INSTALL_HINT = "Reading the iPod's database needs the optional pygpod package. Run the same command with: uv run --extra itunesdb ipod2playlist ... --itunesdb (or install with: uv tool install '.[itunesdb]')"`
  It says "the same command" because `backup --itunesdb` (Task 11) shares it.
- `_import_pygpod()` returns the module:
  - import it with warnings suppressed;
  - on `ImportError`, `raise PygpodMissing(INSTALL_HINT)`.
- `relative_key(song_path, root)` returns `Path(song_path).relative_to(root).as_posix().casefold()`.
  The track key is `"/".join(ipod_path.lstrip(":").split(":")).casefold()`. Matching uses these strings
  only; no iPod path is ever opened.
- `read_itunesdb(root)` copies, then parses the copy:
  1. `db_file = find_itunesdb(str(root))`. If it is None:
     `raise ITunesDBUnreadable(f"no iTunesDB under {root}/iPod_Control/iTunes")`.
  2. `with tempfile.TemporaryDirectory() as tmp:` run
     `shutil.copytree(db_file.parent, Path(tmp) / "iPod_Control" / "iTunes")`. Only reads touch the
     iPod.
  3. `db = pygpod.Database(tmp, recover=False, apply_play_counts=True)`. Any `pygpod.PyGpodError`
     becomes `ITunesDBUnreadable(str(error))`.
  4. Build `tracks = {track_key: DbTrack(title, artist, album, rating_stars, play_count)}`.
  5. Build `playlists = {p.name: [track keys] for p in db.playlists if not p.is_master and not p.is_podcast}`.
     Skip empty playlists.
  6. Return both, before the temp dir is deleted. Do not keep the `db` object.
- `enrich(songs, root, tracks)` returns new `Song`s. **File tags win.** The database fills only the
  scan fallbacks:
  - title, when `song.title == Path(song.path).stem` and the DB title is non-empty;
  - artist, when it is `UNKNOWN_ARTIST`;
  - album, when it is `UNKNOWN_ALBUM`.
  - `rating` and `plays` always come from the DB when the track is found.
  - Songs not in the DB are returned unchanged.
- `save_playlists(playlists, path)`: JSON `{name: [song keys]}`, `indent=2`, `ensure_ascii=False`.
  `load_playlists(path)` returns `{}` if the file is absent.
- `read_or_warn(root)` is the one place with the error handling, shared by `scan` and `backup`:
  - `PygpodMissing` → `raise SystemExit(INSTALL_HINT)` (the user asked for it explicitly);
  - `ITunesDBUnreadable` → print `warning: could not read the iPod's database ({error}); using file tags only.`
    to stderr and return `({}, {})`;
  - otherwise return `read_itunesdb(root)`.
- `scan_with_db(songs, root, tracks, playlists)` returns `(songs, playlists_by_song_key, named)`:
  - `songs` = `enrich(songs, root, tracks)` sorted with
    `sorted(..., key=lambda s: (-s.plays, -s.rating, s.path))`, so the most-played songs come first: in
    playlists, and first in line under the YouTube quota;
  - `playlists_by_song_key` = each playlist's path keys converted to song keys through the enriched
    songs (keys with no song are dropped);
  - `named` = the number of songs whose title or artist `enrich` filled in from the database.

## Task 11: Local audio backup with M3U8 playlists

Files: `src/ipod2playlist/backup.py` (new), `src/ipod2playlist/commands.py` (add `run_backup`),
`src/ipod2playlist/cli.py` (add the `backup` subparser), `pyproject.toml` + `uv.lock` (add
`pathvalidate>=3.3.1`), `tests/test_backup.py` (new). `run_backup` stays thin; the logic is in `backup.py`.

`backup ROOT DEST [--itunesdb]` copies **every** audio file on the iPod, not only the deduplicated
list, into `DEST/Artist/Album/Title.ext`. It writes M3U8 playlists into DEST. It is read-only on the
iPod, resumable, and never overwrites.

**backup.py**
```python
@dataclass
class BackupResult:
    copied: int = 0
    present: int = 0      # already in DEST with the same size (resume)
    conflicts: int = 0    # a different file already has that name; left alone
    protected: int = 0    # .m4p (FairPlay) files copied
class BackupError(Exception): ...
def safe_name(text: str) -> str
    # pathvalidate.sanitize_filename(text, platform="universal").strip(); "" / "." / ".." -> "_"
    # (verified: sanitize_filename("AC/DC") == "ACDC", ("..") == "..", ("") == "", ("CON") == "CON_")
def plan(songs: list[Song], dest: Path) -> list[tuple[Song, Path]]
    # target = dest / safe_name(artist) / safe_name(album) / (safe_name(title) + suffix.lower());
    # a target already claimed earlier in this list gets " (2)", " (3)" ... before the suffix (deterministic).
    # "Claimed" is compared as unicodedata.normalize("NFC", str(target)).casefold(), because macOS
    # folders ignore case: "Hey Jude" and "hey jude" would otherwise land on one file.
def backup(songs: list[Song], root: Path, dest: Path) -> tuple[BackupResult, list[tuple[Song, Path]]]
    # returns the result and the (song, target) pairs now present in DEST, for the playlists
def write_m3u8(entries: list[tuple[Song, Path]], path: Path) -> None
    # "#EXTM3U", then per entry "#EXTINF:-1,{artist} - {title}" and the target's path relative to
    # path.parent, as POSIX. UTF-8, "\n" line endings.
def write_playlists(present: list[tuple[Song, Path]], root: Path, dest: Path,
                    playlists: dict[str, list[str]]) -> int
    # writes DEST/My iPod.m3u8 with all `present` entries, in scan order, and one
    # DEST/{safe_name(name)}.m3u8 per iPod playlist (`playlists` maps name -> path keys from
    # itunesdb.read_itunesdb; pass {} without --itunesdb), mapping keys to targets through
    # itunesdb.relative_key(song.path, root). Returns how many files it wrote.
def summary_lines(result: BackupResult, playlist_count: int, dest: Path) -> list[str]
    # the lines run_backup prints, below
```

Rules in `backup`, in order:
1. **Destination check.** If `dest.resolve()` is `root.resolve()` or lies inside it:
   `raise BackupError("The backup folder must not be on the iPod; choose a folder on this Mac, e.g. ~/Music/iPod backup.")`.
   This check comes before anything is created.
2. `dest.mkdir(parents=True, exist_ok=True)`. Compute the plan.
3. **Classify each target:**
   - it exists with the source's size → `present`;
   - it exists with a different size → `conflicts` (print `! exists, left alone: {target}`);
   - otherwise → to copy.
4. **Space check.** `needed = sum(source sizes to copy)`. If
   `needed > shutil.disk_usage(dest).free`:
   `raise BackupError(f"Not enough space in {dest}: need {needed / 1e9:.1f} GB, {free / 1e9:.1f} GB free.")`.
   Nothing has been copied at this point.
5. **Copy each file:**
   - `part = target.with_name(target.name + ".part")`;
   - `shutil.copy2(source, part)`;
   - if `part.stat().st_size != source size`: unlink `part`, then
     `raise BackupError(f"Copy of {source} was incomplete; re-run backup.")`;
   - `os.rename(part, target)`;
   - print `[{i}/{n}] {artist} - {title}`.
   - A leftover `.part` from an interrupted run is overwritten next time, because it is ours and lives
     in DEST.
6. Count `.m4p` sources in `protected`.

**`run_backup(args)`**
- **Root check.** `args.root` must be a directory, with the same message as `scan`.
- `songs = scan(args.root)`, without dedupe.
- **With `--itunesdb`:** `tracks, playlists = itunesdb.read_or_warn(args.root)` (the same error handling
  as `scan`, defined once in Task 10) and `songs = itunesdb.enrich(songs, args.root, tracks)`. Without the
  flag, `playlists = {}`.
- `result, present = backup.backup(songs, args.root, args.dest)`.
- `k = backup.write_playlists(present, args.root, args.dest, playlists)`.
- Print each line of `backup.summary_lines(result, k, args.dest)`:
  - `{copied} copied / {present} already there / {conflicts} left alone; wrote {k} playlist file(s) to {dest}`;
  - if `protected`: `{protected} songs are .m4p files bought from iTunes with copy protection; they were copied but only play on a computer authorised with that Apple ID.`
- `BackupError` → `raise SystemExit(str(error))`.

**Required tests** (on `fake_ipod`, whose root is `tmp_path / "ipod"` since Task 1; DEST is
`tmp_path / "backup"`, so it lies outside the iPod root)
- **First run.**
  - All 6 files are copied (the duplicate "Hey Jude" too: `The Beatles/Past Masters/Hey Jude.mp3` and
    `The Beatles/1/Hey Jude.mp3`).
  - `Unknown Artist/Unknown Album/QRST.mp3` exists.
  - The bytes of each copy equal the source's.
- **The iPod is untouched.** `snapshot(fake_ipod)` is identical before and after a backup, and nothing
  new appears under the iPod root.
- **Resume.** A second run gives `copied == 0` and `present == 6`.
- **Interrupted copy.** Make `shutil.copy2` raise on the 3rd file via monkeypatch. The first 2 targets
  exist and no target is half-written. The re-run copies the remaining 4.
- **Never overwrite.** A different-sized file already at a target is counted as a conflict, and its
  content is unchanged.
- **DEST inside the iPod.** `DEST = fake_ipod / "backup"` raises `BackupError`, and no directory is
  created on the iPod (`snapshot` unchanged, and `fake_ipod/"backup"` does not exist).
- **Not enough space.** Monkeypatch `backup.shutil.disk_usage` to report 10 bytes free. `BackupError`
  is raised and no file is copied.
- **Name collisions and safety.**
  - `plan` with two songs "AC/DC" / "Back in Black" / "Hells Bells" gives `ACDC/Back in Black/Hells Bells.mp3`
    and `ACDC/Back in Black/Hells Bells (2).mp3`;
  - a title `".."` gives `_.mp3`;
  - titles `"Hey Jude"` and `"hey jude"` by the same artist and album give two distinct targets
    (case-insensitive folders), the second with ` (2)`.
- **Playlist file.** `My iPod.m3u8` starts with `#EXTM3U`, has one `#EXTINF:-1,The Beatles - Hey Jude`
  line, and every path line is relative and resolves (from DEST) to an existing file.
- **CLI.** `backup ROOT DEST --itunesdb` on `fake_ipod_with_db` writes `Road Trip.m3u8` with exactly 2
  entries. Skip this test unless pygpod is installed, using the fixture's importorskip. With a junk
  database (`fake_ipod`), `backup ... --itunesdb` prints the warning and still backs up.
- A `.m4p` file (copy the m4a fixture to `F08/DRM1.m4p`) is counted in `protected`, and the note is
  printed.

**Risk**
- A real iPod over USB 2.0 copies roughly 80–160 GB in hours. Only resumability is tested, not speed.
- Two genuinely different files with the same artist/album/title and the same byte size would be taken
  as "present" on a re-run. That is unlikely, and it never overwrites anything.

Note: `sanitize_filename` caps names at 255 characters, and ` (2)` plus the suffix plus `.part` can push
a name past the 255-byte limit; pass `max_len` with headroom (e.g. 200). An iPod playlist named
`My iPod` would overwrite the all-songs `My iPod.m3u8`; give it a ` (2)` suffix.
